> 日期：2026-09-21 ｜ 环境：回测服务器 186.241.106.174（Docker freqtrade 2026.7，OKX 合约数据）
> 区间：2025-01-11 → 2026-09-20 ｜ 5 主币（BTC/ETH/XRP/SOL/BNB）30m ｜ `config_lzy_超参数优化`（max_open=1，3x）
> 结论先行：**十三个思路全部否决，V4 维持生产；后续 V18–V21 中 V20（极值逆势闸门·减仓）通过全部 15 个主池切分，已定稿为新生产版 `V5`（不替换李志勇）**。V17 用 FreqAI/LightGBM 预测波动做首仓缩放：71 次触发、盈利桶与亏损桶等比例缩小，收益 -23% 而水下不变 → ML 波动预测在 V4 上不提供增量。V15 极值价触发曾是本批唯一正向（主池 +5.0%），但 6 币 OOS 腰斩否决；V16 把"上涨收敛→死叉反弹"反用在多头也没能落地（信号与 V4 入场极少重合，单独持有 10 天净期望 +2.2%、t≈2.1，但 2022 与 OOS 2025 为负、尾部驱动）。两条可复用发现：日线"上涨排列→均线收敛→死叉"确实偏反弹；周线判断趋势用 1 根均线（ma5）优于 2 根。补仓结构（次数/间距/时间/止损）全部是"救援引擎"的一部分，任何削弱都会崩。LLM 闸门（V13）在污染的历史回测里显示风控改善，但必须前向影子验证，不可当证据。

## 0. 起因（用户观察）

1. 均线开始收敛时危险；**上涨排列收敛 → 交汇（ma5 下穿 ma10）后大概率还要反弹**，做空容易被咬
2. **周期越长，判断趋势用的均线应该越少**：周线用 5 或 5/10 就够
3. 危险区（减过仓的）空单有盈利应**提前锁定**，不要等 trailing（0.004/0.03，可能等不到 +3% 就掉头）

## 7. V10 = V4 + 补仓阈值递增（缓解"猛补"）

背景：补仓线按"当前均价水下 4%"判定，补一次后均价被拉近现价，后续补仓只需再跌约 2%/1.3%/1%/0.8%/0.5%（"猛补"）。处理：第 n 次补仓阈值 = `adjust_profit` + `dca_profit_ramp`×(n-1)，上限 20%。

## 10. V13 = V4 + LLM 风控闸门（DeepSeek deepseek-flash）

架构（与策略解耦）：策略内不发网络请求。`utils/llm_gate.py` sidecar 读取策略导出的入场快照，调用 LLM 输出严格 JSON `{action: allow|half|block, confidence, reason}`；策略 V13 只读 `user_data/llm/verdicts.jsonl`。
- `verdict_mode='harvest'`：等价 V4，但每次首仓入场写快照（548 条）
- `verdict_mode='shadow'`：只打日志不改仓位（前向验证用）
- `verdict_mode='half'`：half → 首仓×0.5、block → ×0.25；缺失/过期/异常 fail-open

实测（5 币全期）：裁决 allow 430 / half 86 / block 32（其中 164 笔因超时 fail-open 成 allow）。门控回测：

|---|---|---|---|---|---|
| V4 基线 | 1743.9% | 4.63 | 12.98% | 2.65 | 548 |
| V13 + DeepSeek half/block | 1454.2% | 5.93 | 6.48% | 4.34 | 548 |
| （对照）V13 + mock 规则 | 1408.4% | 5.36 | 12.98% | 2.57 | 548 |

模型理由务实（如"高于ma60达24%且刚现-3.12%急跌，逆势多易转深水"）。**判定：不可作为证据、未上线**。历史回测受污染（模型知识截止晚于区间，等于开卷考试），且 30% 超时 fail-open 有偏；唯一干净的验证是前向影子模式（2-4 周，只记日志不动仓位，再用真实结果给被拦/放行单打分）。已按用户要求暂停。

## 30s. 杠杆 × 止损的缩放关系与容量表（2026-10-23，实测验证；资金放大时用）

**问题**：资金变大后要降杠杆（为了交易所名义上限/绝对风险），`stoploss` 要不要跟着改？

**三条尺子**（L=杠杆、s=stoploss（ROE 口径）、div=分腿数）：

```
价格止损距离 = |s| / L            ← 决定"哪些单会被扫"，必须恒定（定版 = 0.767%）
每笔钱包风险 = |s| × 0.98/div     ← 单笔最大亏损占钱包
名义敞口     = L × 0.98/div       ← 决定收益与爆仓距离
```

**结论：必须同比例缩放 `stoploss = -0.023 × L/3`。** 收益只取决于**名义敞口**（`L×0.98/div`），与杠杆本身无关；杠杆只影响 ①保证金占用 ②交易所名义上限（容量）③ROE 数字（止损同步缩放后即为装饰）。

**实测验证**（主池 5 币，20250111→20261019；变体为 70 服 `strategies_lev/ChanLev1.py`、`ChanLev2.py`，子类覆盖 `stoploss` 与 `leverage()`）：

|---|---|---|---|---|---|---|---|---|
| 3x / div2（定版） | -2.30% | 1.47× | +38,795% | — | 1.95 | 5.14 | 15.06% | 711 |
| **2x / div2** | **-1.533%** | 0.98× | **+5,402.73%** | 866% | 2.03 | 5.06 | 11.51% | 710 |
| 3x / div3（对照） | -2.30% | 0.98× | +5,397% | — | 2.03 | 5.06 | 11.51% | 710 |

**2x/div2 + 缩放止损 ≡ 3x/div3，逐项一致**（5402.73 vs 5397、DD/PF/Sharpe 完全相同，笔数 710/710）→ **名义敞口相同则收益曲线相同，误差仅 0.1%**（来自取整）。杠杆轴被证实为纯缩放。

## 30t. 缠论移动止损的完整轴：启动线 / 距离 / 时间 / 时间+浮盈（2026-10-23，全部否决）

**实现（关键）**：freqtrade 没有原生"时间门控 trailing"。用临时策略 `ChanTrailT`（= `ChanlunStrategy30m` 副本）在 **`custom_exit`（每根 K 都会被调用）** 里切换原生 trailing 属性：

```python

    self.trailing_stop = True          # distance/offset 同时设好
self.trailing_stop_positive = dist     # ROE 口径

self.trailing_only_offset_is_reached = False   # 换单时复位 trailing_stop=False
```
